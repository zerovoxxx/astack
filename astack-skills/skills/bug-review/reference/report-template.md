# BUG 报告输出模板

Layer 5 输出时使用此模板。报告写入 `docs/bugreport/bug_report_YYYYMMdd_xxxx.md` 文件。

## 文件头模板

报告文件开头必须包含以下元数据块：

```markdown
# FinClaw BUG 审查报告

| 字段 | 值 |
|------|-----|
| **审查日期** | YYYY-MM-dd |
| **审查模式** | 全仓扫描 / 每日增量 / 模块定向 / PR 增量 / 全仓扫描（并行合并） |
| **审查范围** | 描述扫描了哪些模块/文件/PR |
| **分支** | 当前 git 分支名 |

---
```

文件头之后依次输出：BUG 条目 → 观察项 → 趋势对比 → 统计摘要。

## 单条 BUG 模板

```markdown
### [BUG-NNN] 标题（一句话描述问题本质）

| 字段 | 值 |
|------|-----|
| **等级** | P0 / P1 / P2 / P3 / P4 |
| **置信度** | High / Medium / Low |
| **影响范围** | 受影响的模块、功能、用户场景 |
| **触发条件** | 在什么情况下会触发此 bug |

**证据**

引用具体代码位置和关键代码片段（文件路径 + 行号），说明问题在代码中的表现。

**根因**

解释 bug 的形成机制：为什么这段代码会产生错误行为，而不仅仅是描述错误现象。

**修复建议**

给出最小修复方案。如果有多种修复路径，列出推荐方案和备选方案。
对 P0/P1 级别，修复建议必须具体到"改哪个函数/哪一行/改成什么"。

**建议验证方式**

说明如何验证修复是否生效：单元测试、手动操作步骤、或需要关注的日志输出。

**关联**

关联的反模式编号（如 P12）、黄金法则编号（如 R5）、或历史迭代编号。无则填"无"。
```

## 观察项模板

置信度为 Low 或归因未完成（5 题未答满）的问题，用简化模板：

```markdown
### [OBS-NNN] 标题

| 字段 | 值 |
|------|-----|
| **疑似等级** | P? |
| **置信度** | Low |
| **位置** | 文件路径 + 大致行号范围 |

**现象**：简述观察到的可疑行为或模式。

**待验证**：说明需要什么额外信息才能确认或排除。
```

## 趋势对比

与上一次同模式扫描报告对比（如果 `docs/bugreport/` 中存在上一次报告）：

```markdown
---

## 趋势对比

| 指标 | 上次（YYYY-MM-dd） | 本次 | 变化 |
|------|-------------------|------|------|
| BUG 总数 | X | Y | +/-N |
| P0+P1 数 | X | Y | +/-N |
| 观察项数 | X | Y | +/-N |

**持续存在的问题**：列出上次报告中也出现、本次仍存在的 BUG（按标题匹配）。
**本次新发现**：列出上次报告中未出现的 BUG。
**已消失的问题**：列出上次报告中存在但本次未发现的 BUG（可能已修复）。

**趋势分析**：（一两句话描述代码质量变化方向）
```

无上一次报告可对比时，标注"首次扫描，无历史对比数据"。

## 统计摘要模板

报告末尾输出：

```markdown
---

## 审查摘要

| 维度 | 数据 |
|------|------|
| 扫描模式 | 全仓扫描 / 每日增量 / 模块定向 / PR 增量 |
| 扫描范围 | X 个模块，Y 个文件 |
| 确认 BUG | P0: a / P1: b / P2: c / P3: d / P4: e |
| 观察项 | N 条 |
| 置信度分布 | High: x / Medium: y / Low: z |

### 建议优先修复

1. [BUG-001] 标题 — P0/High
2. [BUG-002] 标题 — P1/High
...

### 观察名单

1. [OBS-001] 标题 — 待验证内容
...
```

## 使用说明

- 报告输出路径：`docs/bugreport/YYYYMMdd/bug_report_YYYYMMdd_xxxx.md`（`xxxx` 为 4 位随机字母数字字符，按日期归档到子目录）
- BUG 编号从 001 开始递增，同一次审查内唯一
- 观察项编号从 OBS-001 开始递增
- 同根因的多个表象合并为一条 BUG，在"证据"中列出所有表现点
- 报告按等级降序排列（P0 在前），同等级内按置信度降序
- 全仓扫描时，可按风险域分节（每个 Tier/模块一个小节），末尾汇总
